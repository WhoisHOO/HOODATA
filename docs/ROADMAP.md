# HOODATA 로드맵

센서, 장치, 파일 등 데이터가 들어오는 곳이면 어디서든 값을 받아 다음 세 가지를 하는 도구입니다.

1. **대시보드**: 채널마다 지금 값, 그래프, 상태(정상·주의·이상)와 기간별 통계를 보여 줍니다.
2. **노이즈·특이사항 기록**: 노이즈 수준은 따로 추적하고, 끊김·튐·멈춤 같은 특이사항은 언제, 어디서, 얼마나,
   왜 이상으로 봤는지와 함께 기록합니다.
3. **패턴 분석**: 어떤 상황(시간대, 요일, 다른 센서의 상태, 앞서 일어난 다른 특이사항)에서 어떤 특이사항이 평소보다
   자주 오는지 찾아 보여 줍니다.

범용 엔진을 먼저 만들고, 분야별 버전(스마트팜, 양식장, 공장 설비 등)은 그 위에 **프로필**(채널 종류, 단위, 정상 범위,
검출 설정의 묶음)로 얹습니다.

## 구조

```
 수집                      처리                          저장                 화면
 ─────────────            ─────────────────            ──────────────       ─────────────────
 이 PC 상태값 ─┐           채널 찾기·만들기              값 (원본, 보관 기간)   대시보드
 파일·폴더    ─┤           특이사항 검출 (채널마다)      1분 요약              특이사항 기록
 HTTP 받기    ─┼─ 값 ──▶   노이즈 추적          ──▶     특이사항        ──▶  패턴
 MQTT         ─┤           1분 요약                     패턴                  데이터 연결
 Modbus TCP   ─┤                                                             설정
 시리얼       ─┘           패턴 분석 (주기적·요청 시) ◀── 1분 요약 + 특이사항
```

- **값**은 (채널, 시각, 실수) 하나입니다. 시각은 UTC 밀리초로 저장하고 화면에서 이 PC의 시간대로 바꿉니다.
- **1분 요약**은 개수, 최솟값, 최댓값, 평균, 표준편차, 노이즈 추정값입니다. 긴 기간의 그래프와 패턴 분석은 이것으로
  하므로, 원본 값은 보관 기간(기본 30일)이 지나면 지워도 됩니다.
- 장치가 보내는 형식은 자동으로 알아봅니다: JSON(`{"temp":23.5}`), `이름=값`, `이름:값`(아두이노 시리얼 플로터),
  CSV 한 줄, 숫자만. 시각 필드(`ts`, `time`, `timestamp`)가 있으면 그 시각을, 없으면 받은 시각을 씁니다.

## 특이사항 (첫 버전)

| 종류 | 이름 | 판단 기준 (요약) |
|---|---|---|
| gap | 끊김 | 평소 들어오던 간격보다 훨씬 오래 값이 없음 |
| spike | 튐 | 바로 앞 값들의 중앙값에서 크게 벗어났다가 곧 돌아옴 (Hampel 방식, 중앙값·MAD 기준) |
| step | 수준 변화 | 갑자기 크게 벗어난 뒤 돌아오지 않음 |
| stuck | 멈춤 | 평소 변하던 값이 평소 가장 길게 같던 시간보다 훨씬 오래 그대로 |
| range | 범위 밖 | 사용자(또는 프로필)가 정한 범위를 벗어남 |
| noisy | 노이즈 증가 | 노이즈 추정값(1차 차분의 중앙값 기반 표준편차)이 평소의 몇 배 |
| unusual | 평소와 다름 | 같은 시간대의 평소 범위(지난 며칠)를 벗어난 상태가 이어짐 |

- 민감도는 숫자 대신 **낮음·보통·높음**으로 고릅니다.
- 검출기는 충분한 값을 본 뒤에야 판단합니다(학습 중 표시).
- 각 방법의 정의, 민감도별 기준값, 평가 결과와 출처(논문)는 [METHODS.md](METHODS.md)(영어)에 있습니다.
  출처의 DOI는 doi.org에 등록된 제목과 맞춰 확인했습니다.

## 패턴 분석

1. 데이터가 있는 시간을 5분(많으면 더 긴) 칸으로 나누고, 칸마다 **상황**을 붙입니다: 시간대(00–04시, 04–08시 같은
   4시간 단위), 요일과 평일·주말(2주 이상일 때), 다른 채널이 높음·낮음(그 채널 값의 위·아래 20%), 켜짐·꺼짐처럼 값이
   네 개 이하인 채널은 그 값.
2. 채널·종류별 특이사항이 시작된 칸의 비율을 상황별로 비교합니다:
   배수(lift), 건수, 그 상황이 차지한 시간, Fisher 정확검정의 유의확률, 여러 번 검정한 것의 보정(Benjamini–Hochberg).
3. 조건 두 개의 조합까지 찾습니다(부분집단 발견). 조합은 각 조건 하나보다 뚜렷하게 나을 때만 남깁니다.
4. **선후 관계**: A 특이사항(또는 스위치가 어떤 값으로 바뀐 순간) 뒤 5분·30분·2시간 안에 B 특이사항이 오는 횟수를
   우연일 때의 기대값과 비교합니다. 앞에 오는 일은 상황이 아니라 이 선후 관계로 찾습니다.
5. 결과는 문장으로 보여 줍니다. 예: "습도 높음(≥ 86.3%) · 00–04시일 때 평소의 6.1배 (그 상황은 전체 시간의 9%,
   그때 일어난 것 15건 / 전체 19건)".

한계: 찾는 것은 **연관**이지 원인이 아닙니다. 예를 들어 온실 데이터에서는 토양 센서 튐이 "기온 낮음"과도 함께
나오는데, 습한 시간이 곧 추운 밤 시간이기 때문입니다. 건수가 적으면 결과를 보류하고 그렇다고 표시합니다.
